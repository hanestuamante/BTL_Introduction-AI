# ADR-001: Kiến trúc solver và phạm vi MVP

- Trạng thái: **Accepted**, 19/09/2026.
- Hai puzzle: Pipes non-wrap và Futoshiki.
- Hai chiến lược: DFS iterative và Greedy Best-First Search.
- Solver dùng chung `SearchProblem`; UI và benchmark chỉ tiêu thụ kết quả/event.
- State là tuple bất biến, hành động gán ô tiếp theo theo thứ tự hàng-cột.
- Tkinter chạy trên main thread; solver chạy worker thread và giao tiếp bằng queue.
- Input được tự sinh bằng seed, kiểm tra schema, checksum và đúng một nghiệm.

Hệ quả: GBFS không đảm bảo tối ưu; DFS có thể timeout ở input lớn. Benchmark tách lượt đo thời gian và lượt `tracemalloc` để tránh trộn overhead.
